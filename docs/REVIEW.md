# 开发迭代与后续计划

[← 文档首页](README.md)

这一章记录方案怎样演变：哪些被采用，哪些被调整，哪些被放弃，以及原因。

## 1. 揭示 Shader：Shader Graph → 手写 HLSL

| | 第一版（Shader Graph） | 第二版（手写 HLSL） |
|---|---|---|
| 两侧表面 | 两组 PBR 贴图 | 工笔风格光照 + PBR |
| 揭示遮罩 | 世界空间球，`Smoothstep` 软边 | 世界空间球 + 物体空间三层噪声边缘 + 发光带 |
| 描边 | 无 | 独立 pass，随揭示收缩 |
| 纹理投影 | UV | UV 或三平面 |
| 阴影 / 深度 | Shader Graph 自动生成 | 手写，与揭示函数共用 |

**为什么换**：

1. 两侧都是 PBR 时，玩家读不出「这是两种不同的东西」，只像换了一张贴图；
2. 风格化光照需要阶梯量化、阈值偏移的笔触、量化的附加光源循环，在 Shader Graph 里要大量 Custom Function 节点，不如直接写；
3. 描边需要一个独立的 pass，并且和颜色 pass 使用**同一个**揭示函数，Shader Graph 在 URP 下做不到；
4. 手写之后，揭示函数只写一次，所有 pass 都引用它。

**保留了什么**：属性名 `_HitPosWS` / `_Radius` / `_Softness` 不变，原有的射线脚本不需要修改；PBR 侧兼容第一版的粗糙度贴图；`_RevealToStylized` 的反向模式让第一版场景里的金属材质原样迁移过来。

## 2. 局部揭示：以零件为单位 → 以器物为单位

第一版射线以单个 Renderer 为单位：在多零件器物上移动时，每换一个零件就从零开始；滑到另一件器物时，前一件停在原样。改为 `RevealPatchDriver` 以器物根节点为键管理，并加入平滑跟随和统一消退。见 [反馈](FEEDBACK.md#1-局部探索以整件器物为单位)。

## 3. 提示：形状 → 质地

轮廓缩略图海报让玩家可以只看形状就放对，射线和材质成了可有可无的装饰。我把三个房间的轮廓海报统一关闭，改为只用质地样片提示。这是整个项目最重要的一个设计调整：**提示必须指向核心机制，而不是绕过它。** 见 [交互 · 缩略提示](INTERACTION.md#7-缩略提示告诉玩家还差什么)。

## 4. 碰撞体：整件包围盒 → 切块凸包

整件包围盒让射线在零件之间的空隙也能命中，器物也会悬在桌面上。直接用凸网格又会填平凹处，并超过 256 面的上限。最终方案是按位置切块，每块取极值点后生成凸包。见 [工具链](TOOLS.md#31-碰撞体按零件切块的凸包)。

## 5. 贴图生成：文生图 → 种子图 + 图生图

| 尝试 | 结果 | 处理 |
|---|---|---|
| SD 1.5 | 笔触感弱，结果接近照片质感 | 改用 Anima + texture LoRA |
| 笔触直接文生图 | 画面里出现铅笔、人物等主体 | 改为程序化种子图 + 图生图 |
| 以现成贴图为输入做图生图 | 质量稳定，但结果是第三方素材的变体 | 只做内部对比，不进游戏，不公开 |
| 直接导入生成图 | 四边接不上 | 增加错位交叉淡化的平铺处理 |

## 6. 考虑过但没有采用的方案

| 方案 | 不采用的原因 |
|---|---|
| 揭示后永久保持（射线离开不退回） | 局部探索会变成「把整个房间刷一遍」，失去「停下来看」的节奏；永久保持只留给放对后的缩小模型和整房恢复 |
| 屏幕空间揭示遮罩 | VR 中左右眼看到的圆不在同一个三维位置 |
| 每个命中状态复制一份材质 | 材质数量随交互增长，破坏批处理 |

## 7. 后续计划

| 优先级 | 内容 |
|---|---|
| 高 | 真机验收：四种情况的 CPU/GPU 帧时间、双眼一致性、交互尺度 |
| 高 | 整房恢复完成后停止每帧写属性，释放控制权 |
| 中 | 房间盒支持旋转 |
| 中 | 平铺处理改为基于图块合成，消除过渡带的重复图案 |
| 低 | 材质族增加物理参数（质量、摩擦、碰撞声），让手感也随质地变化 |
