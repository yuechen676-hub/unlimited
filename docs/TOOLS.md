# 编辑器工具链

[← 文档首页](README.md) · 相关：[材质库](MATERIAL_LIBRARY.md) · [AIGC 贴图流程](AIGC.md) · [验证](VALIDATION.md)

## 1. 原则

我给工具定了几条原则：

- **场景改造全部由工具完成**，不手动拖拽。工具可以重复执行，结果可以对比。
- **只修改场景副本**，原场景和原资源保持不变，随时可以回到起点。
- **每个会改场景的工具都配一个只读模式**：先检查、写日志，确认后再应用。
- 所有工具都能在 batch mode 下执行（`-executeMethod`），不开编辑器界面也能跑。

## 3. 几个值得展开的工具

### 3.1 碰撞体：按零件切块的凸包

原来每件器物的根节点上只有一个整件碰撞盒：射线指向零件之间的空隙也会命中，器物也会悬在桌面上方。换成网格碰撞体时又有两个限制：

- 器物松手后受重力，带刚体的网格碰撞体**必须是凸的**，直接用凸包会把凹进去的部分填平；
- 物理引擎的凸包**最多 256 个面**，零件的网格很密，直接计算会超限。

所以我让工具按位置把每个零件切成若干块，每块只保留在若干个方向上最靠外的点，再生成凸包。凸包形状基本不变，面数远低于上限，射线指到哪件就命中哪件。

### 3.2 石台：代码生成的网格

我把一号房的桌子换成代码生成的深色石台：每个槽位一个浅凹槽，台面和凹槽边缘各有一圈细白线。凹槽的位置直接从槽位读取，槽位移动后重新执行即可，不用回到 DCC 软件改模型。

### 3.3 槽位特效：不改原资源的变体

槽位放对时的光效沿用第三方粒子包里的圆形传送特效。为了贴合方形凹槽，我让工具建一个预制体变体，原预制体和它的材质、贴图都不动：

| 原效果 | 变体 |
|---|---|
| 地面上扩散的圆环 | 方环贴图（代码生成） |
| 地面上的圆形柔光 | 方形柔光贴图（代码生成） |
| 从圆周升起的光点 | 发射形状改成方框 |
| 圆柱形的光柱网格 | 四棱柱网格（代码生成） |

光点本身、渐变贴图，以及各粒子系统的大小、寿命和颜色曲线都保持原样。尺寸按原特效的单位换算：光柱边长 0.42 × 8 = 3.36 个单位，整体缩放后正好等于 0.42 m 的凹槽；方环贴图的外沿比例（0.84）也按这个尺寸计算，让地面的方环和光柱对齐。

### 3.4 塔外光束：先预览再应用

我把塔外 6 道光束改成舞台灯式的交叉：左右两两成对，往对面倾斜，在塔前交叉成 X；三对前后拉开，环绕镜头从侧面也能看到交叉。`Preview` 在内存里摆好后渲染几个角度的截图，不保存场景；确认后再 `Apply`。

光束着色器是普通的半透明混合，只有颜色的透明度决定亮度，调得太高会把被挡住的塔墙刷白。所以我复制了一份材质单独调亮度，第三方原材质不动。

### 3.5 审计：用文本对照配置

审计工具把每个房间的器物 ID、槽位 ID、样片材质、缩小模型和声音写成文本。三个房间 18 对器物和槽位的一致性检查从「打开场景逐个点」变成「比较两份文本」。

## 4. Batch mode 用法

```text
Unity.exe -batchmode -quit -projectPath <工程> -executeMethod StylizedRevealRoomAudit.Run -logFile <日志>
```

- 工具通过环境变量（如 `SR_AUDIT_OUT`）接收输出路径；
- 会改场景的工具把每一项改动写进日志（`Logs/*_apply.txt`）；
- PlayMode 测试同样用 batch mode 执行，见 [验证](VALIDATION.md)。
